# ModelRadar

菜单栏常驻的「模型速度与成本性价比定位图」：抓 Artificial Analysis / OpenRouter /
DataLearner / OpenRouter 周用量，并用 models.dev 作模型目录交叉源，
算 Pareto 前沿，画成一张自包含 SVG 塞进 NSPopover，并在数据更新时提示。

`models.dev` 只补 OpenRouter 缺失的上下文与名义价格，不覆盖实时报价；
源失败时保留对应状态，不让整轮抓取失败。

纯 Python（抓取/渲染）+ 纯 AppKit（状态栏组件），无第三方 UI 框架。
HTML 解析走标准库；Progress 的官方公开 AES-GCM 数据包使用 `cryptography` 验证解密，
通过运行环境的 `python -m pip install -r requirements.txt` 安装。
缺少该依赖时 Progress 标记缺失，不能把旧分数或零值当作新数据。

```

  runtime.env                           MR_REPO / MR_DATA / MR_PYTHON，build 生成
  data/                                 ModelRadar.db（历史台账）+ latest.json/js + chart.html + logos/
```

**为什么这么分**：项目起初住在一个按会话创建的临时目录里，解释器也被写死成那个目录下的
路径。临时目录一被清理，菜单栏就只剩"找不到图表数据"，
而每日爬虫会天天失败且没有任何可见症状。现在仓库可随意挪动，SQLite 历史不跟着走。

### 评测版本与历史

来源：2026-10-28 用户要求提取 Progress 分数用于节点、族和厂商悬停，
并禁止大版本换代后继续沿用旧评测节点。复用现有 SQLite 两张表，不新建重复模型目录。

| 表或载荷 | 新字段 | 需求映射与语义 |
|---|---|---|
| `snapshots` | `evaluation_version TEXT NULL` | 标识该次评测快照或合并基线所属版本，按现有 `source` 区分 Intelligence、Progress 与非评测来源 |
| `series` | `evaluation_version TEXT NULL` | 让每个时间序列观测携带评测版本，不能把跨版数值当连续涨跌 |
| 模型、原始 AA 行、diffbase 行 | `evaluation_version` | 贯穿采集、合并、沿用与历史对比的版本证据 |
| 模型、原始 AA 行 | `aa_slug` | 官方链接中的型号档位标识，用于 Progress 精确关联，禁止按模糊型号把分数广播到全族 |
| 模型 | `progress_index`、`progress_version` | 精确型号及档位匹配的 Progress 分数和独立版本，不参与 Intelligence 排名和成本前沿 |

版本来自官方当前方法学。迁移仅加列，不改写原始历史 payload，不按日期猜旧版本。
旧数据没有版本证据时保留 NULL。未知版本和不同版本的旧节点不沿用到当前图，
来源：2026-11-04 用户要求小版本连续比较，仅首位大版本变化重建比较基线。
例如 5.0、5.0.1 和 5.1 继续使用原有差分、累计、回溯及周变化规则，跨小版本明细标注双方版本。
未知版本或不同大版本之间重建比较基线，不逐模型报评分和每任务成本涨跌。
旧节点沿用仍要求完整版本一致，原始历史版本和保留期限不变。
Progress 缺失不记为零，也不把一个型号最佳档的分数复制到其它档位。

**2026-11-15 起榜单换成每个 release 一行**：Progress 与每任务耗时都只给 `release.slug`
（Progress 另有 `effort.slug`，耗时用 `suffix`），同一个 `aa_slug` 对应同族多个档位。
两侧都用同一套 `(release, 档位)` 索引定位：档位优先取 `effort.slug`，其次 `suffix`，
最后从名字括号取；`aa_slug` 本身就是每档 slug 的旧格式回落为唯一匹配。候选不唯一、
版本不一致、当期缺值一律留空，仍不向同族其它档广播。

**沿用行补回同轮旧读数**（`restore_carried_metrics`）：`attach_progress` 与
`attach_task_times` 跳过 `carried_asof` 行 —— 拿今天的值冒充旧读数是不对的。但沿用行
该有的那两项旧读数在台账里，所以补一步：按 `carried_asof` 取**同一轮**的
`aa_progress` / `aa_times` 快照（三份快照在一轮里各差几秒，Progress 与耗时都在 AA 的
`ts` **之后**落地，因此同轮判据是 `ts>=asof` 且落在 300 秒窗口内；取不到才退回
`asof` 之前最近一条），加同样的版本门槛后回填 `progress_index`、`time_per_task_s` 与
`output_tokens_per_task`。上游当期缺值仍留空，耗时缺口交给
`derive_missing_task_times` 用回填出的输出量派生。台账（`series`）本来就跳过沿用行，
回填不污染趋势；渲染侧只多一个 `opacity:.6` 与「沿用 MM-DD」提示。

### 抓取预算

抓取预算：每轮所有网络请求共用 240 秒墙钟上限，每个来源最多 100 秒（含子页面、manifest 与重试）。
单次 HTTP 尝试最多 30 秒；任务耗时页面与来源共用 100 秒预算，建连单独封顶 10 秒；都不能超过整轮剩余预算。
传输统一使用 macOS 自带 `/usr/bin/curl`，父进程在截止时终止并回收下载进程，覆盖等响应头与慢滴正文。
外网请求跟随本机系统代理（`MR_FETCH_PROXY`、`HTTPS_PROXY` 或 macOS 网络配置），代理连不上才回退直连；本地与私网地址始终直连。
2026-11-15 复测：AA 榜单 1.44 MB、models 1.28 MB、trends 0.77 MB，正文没有变大；
当日失败是本机到 Vercel 的直连退化到 0.1–2 KB/s，同一时刻系统代理 24–48 KB/s，放大超时无法解决。
Logo 最多使用剩余预算中的 10 秒，Logo 读写失败不阻止数据发布。
组件仍以 300 秒作最后保护，网络截止后保留 60 秒给本地处理与渲染。
AA 成功而副源失败时，发布本轮 AA 历史与 `degraded` 结果，组件显示“部分更新”。
AA 失败时只沿用已标记的旧快照，不把旧值重新写成历史观测；没有旧快照时仍报无数据。
2026-10-30 截图回归：主源抓取失败时保留上次发布的完整模型与数据时间，仅更新失败状态。
没有已发布页面时按来源台账重建旧图。任务耗时或 Progress 来源失败时沿用对应来源的已知值并标记来源陈旧；旧任务耗时不写入新的历史观测。

### 时间指标

2026-11-04 榜单将速度列改为任务分钟、延迟改为首回答 token，旧总响应列移除。
新版以官方 `initialModels` 按 `aa_slug` 精确读取 `outputSpeed` 与 `timeToFirstToken`；
不把任务分钟当 TPS，不把首回答延迟当首块延迟，缺少新版模型数据时拒绝解析。
旧总响应没有新观测时留空，不能从任务耗时反推。错列历史只隔离对应轮次与字段，原记录保留。
2026-11-04 后续要求：按叶子表头的语义和单位匹配列，允许重排、插入无关列及删除可选列。
必需列缺失、重复、单位未知或表格不唯一时拒绝解析，不使用数值启发式猜测。
完整 AA 公开 HTML 作为 `snapshots.source=aa_html` 保留，复用原表和保留期限，供同轮重解析。
被隔离的 TPS 在发布副本中沿用同大版本上一轮可信值，以 `tok_s_asof` 标记时间；
该字段仅供图表及表格展示，不写入新观测或比较基线。对应来源为用户要求保留 TPS 圆面积。

来源：2026-10-28 用户要求获取首块延迟、总响应时间、每任务耗时并研究展示。

| 字段 | 上游与定义 | 历史与限制 |
|---|---|---|
| `ttft_s` | 主榜 `Latency — First Chunk (s)`，请求到第一块返回内容 | 沿用既有字段名，不能解释为纯思考时间或最终回答首字延迟 |
| `total_s` | 主榜 `Total Response (s)`，基准响应时间 | 原始快照已有；从本次起加入 `series`，不是 Intelligence 任务的实测耗时 |
| `first_answer_s` | 新版 `initialModels.timeToFirstAnswerToken`，首回答前等待（含输入/排队） | 仅用于 `total_s` 完全缺失时的思考时间兜底；不写进 `total_s`，不进历史序列与比较基线 |
| `time_per_task_s` | `/models` 公开模型数据包 `intelligenceIndexTimePerTask`，原始单位秒 | Intelligence 同版本任务的加权生成耗时估计，不含 TTFT 与额外开销；按官方型号档位 slug 匹配 |
| `output_tokens_per_task` | 同一份 `/models` 数据包的 `intelligenceIndexOutputTokensPerTask.output` | 每任务输出 token（含 reasoning + answer）；仅用于派生缺失的任务耗时，不写入历史序列 |

`tools/backfill_response_times.py` 默认只读预览，加 `--apply` 才补录上述两项历史序列。
仅从成功 AA 原始快照读取，保留原时间戳及已知版本；未知版本仍为 NULL。
补录不覆盖既有序列、不修改原始快照、不从价格或 TPS 反推任务耗时。
主榜实测速度使用标准化 token；任务耗时公式使用原生 token，不能混用。
官网任务耗时图显示分钟，客户端将原值除以 60；本地统一存秒，不能直接把原值当分钟。
总响应列的官方口径是首块延迟加 `(reasoningTokens + 500) / 输出速度`；
首块可能是推理 token，因此 `total_s - ttft_s` 不能当作纯回答生成时间或思考时间；
`前500 TPS` 用的正是这个窗口（推理 token + 500 个回答 token），所以它含首块后的推理与思考等待。
2026-10-29 核对官方客户端与模型数据包：总响应公式为
`首块 + (reasoningTokens + 500) / 输出速度`。
当前关注节点的 16 项使用 `reasoningTokens=2000`，因而折算前500速度约为输出速度的五分之一。
方法学在缺少平均推理用量时采用 2k 默认预算，但公开数据不区分单项是否恰好实测为 2000。
这不是独立测出的吞吐下降，不以该倍率判断厂商降速或任务效率。
任务耗时独立保存为 `aa_times` 原始快照，并进入 `series`。
来源：2026-11-01 用户要求任务耗时与 TPS 共用变化提醒阈值。
两项均复用 `MOVE_PCT`（当前严格大于 20%），任务耗时从有可比基线后参与提醒，旧快照缺值不补造。
抓取时间卡片的本轮、历史与累计记录随圆面积指标切换，其他指标记录保留。
每项变化后面跟一句关联读数：另一项变化多少、本项符不符合固定输出量下的反比、差几个百分点。
判定容差是 `INVERSE_TOL_PP`（5 个百分点）：实测 1450 对同轮变化，偏差中位 0.0、p95 1.9，
5pp 以上只有 1.6%，那部分是真偏离而不是采证噪声。
改为同轮对比、非同比；基准口径不同，关联不证明因果 —— 这句只在浮层最后一行（`move_hint`）说一次，
不再逐条重复。
旧载荷缺少按指标保存的历史明细时，不展示无法拆分的旧提醒，待后续抓取产生对应记录。
不存在原始任务耗时的旧快照保持缺失，不从价格或基准总响应补造历史。

展示层的三项派生（不落库、不进历史序列）：

- `任务耗时(估)` = `time_per_task_s` 原值，按秒保存。官方口径只估解码生成，
  不含首块延迟（TTFT），也不含判分/PDF/OCR 等额外开销；客户端只换显示单位，不改数值。
- `time_per_task_est_s` = `output_tokens_per_task / speed`，只在官方耗时缺失时派生。
  速度层级与 `estimate_missing_tok_s` 完全一致：实测 → 同族插值/锚点 → 同词根锚点 → 同级参照带。
  有速度点估计时给 `time_per_task_est_s` 与 `time_per_task_est_range`（由速度区间反比换算）；
  只有速度参照带时只给 `time_per_task_band`，不给中心值。所有派生值带 `time_per_task_est`，
  显示为 `≈`，**不写入** `series`/比较基线，也不覆盖 AA 官方 `time_per_task_s`。
  不从总价 ÷ 输出单价反推：总成本混了输入、缓存读/写与输出，实测会把输出量高估中位 3.6 倍。
- `思考时间` = `max(0, total_s - 500 / tok_s)`，只在 `total_s` 与实测 `tok_s` 都为正时计算。
  它实际是**首回答前等待**，包含输入、排队与思考；差值为负超过 1 秒时留空，
  不用推估速度凑公式，也不拿 `ttft_s` 冒充。
  2026-11-04 后续要求：新版榜单已移除旧总响应列，只有 `total_s` **完全缺失**时退回官方
  `timeToFirstAnswerToken`（存为 `first_answer_s`，即首回答前等待本身，不再减 `500 / tok_s`）。
  `total_s` 有值但无效（`0`、负数、非有限数）或与速度矛盾时仍留空，不拿另一个口径掩盖对不上的数据。
- `思考前摇` = `思考时间 / time_per_task_s`，以百分比显示。分母须为有效正数，
  缺失不记零，也不把超过 100% 的值截断。这是不同基准的估计值之比，不是任务内时间分解。
  按用户 2026-10-29 的要求，它替换原 `前500 TPS` 列；后者由上游推理预算和 TPS 决定，
  无独立性能信息，不再重复展示。
- 思考时间与思考前摇**取不到就整段不出现**，不写 `—` 占位：单个点缺值时不显示该段，
  整族/整表都没有时表头列一起不渲染，脚注也去掉对应解释。

时间显示自带单位：不足 60 秒写 `s`，60 秒及以上写 `min`，先 half-up 到一位小数并去掉尾零
（`17.25→17.3s`、`59.95→1min`、`3599.9→60min`、`0s`）；缺失、负数、布尔与非有限数写 `—`。
Python 与看板 JS 都用 `floor(x*10+0.5)/10`，并共用同一个已舍入秒值判断门槛、换算分钟。
原始载荷与数据库仍存秒，排序仍按秒，因此混合单位时表头不再写死 `s`。

用户要求在三处可见：族卡列、单个气泡悬停、看板完整数据表；族卡与完整数据表的可见表头
统一写 `任务耗时(估)`，悬停说明与脚注写明官方只估解码、不含 TTFT 与判分/PDF/OCR 开销，
并说明“思考时间含输入/排队等首回答前等待；思考前摇为不同基准的估计值之比”。

### 气泡大小模式

来源：2026-10-29 用户要求新增开关，关闭时按 TPS 显示，开启时任务耗时越少面积越大。
默认关闭，保留既有 TPS 半径公式与推估、参照带；切换只影响大小，不影响位置、排序和前沿。
任务模式使用当前上图且有有效任务耗时的节点作为缩放域：

```
u = (log10(t_max) - log10(t)) / (log10(t_max) - log10(t_min))
area_fraction = 0.04 + 0.96 * clamp(u, 0, 1)
radius = max_radius * sqrt(area_fraction)
```

全部有效耗时相同时 `u=0.5`。缺失或非正耗时使用更小空心占位，不用 TPS 或同族推估补任务值。
u 按 log10 反比归一，和 x 轴成本轴用同一种对数压缩；面积分数直接线性跟上 u，
不再额外乘 u² 做中低段对比。ln 与 log10 在比值里只差一个常数倍，数学上完全等价，
所以这次真正改变的是去掉 u² 的非线性对比，不是把归一化换成另一种底数。
同一对数域里每差一个数量级，u 走固定一步（10→100→1000 的两数量级域为 .5），
面积分数也等步下降（1→.52→.04）。原数据跨约 28 秒至 52 分钟，直接倒数会让慢任务圆过小；
保留 .04 面积下限后，面积范围为 1:25、半径范围为 1:5，既能区分任务效率，也保留可见性。

#### 全局低分惩罚（任务耗时模式下的第二级开关）

来源：2026-11-06 用户要求，任务耗时模式下低分档不该和满分档用同一条耗时曲线显得一样大，
需要一个开关按"分数低就成比例缩小"整体收缩。**只有这一条附加视图**，不新增第三种气泡定义；
开关只在任务耗时模式开启时出现，默认关闭，关掉再打开任务模式仍保留上次选择
（状态栏存 UserDefaults，看板存自己的 `localStorage` 键）。

收缩强度 λ 是**全图一个数**，由爬虫算一次后随载荷发布（`task_size_penalty`），两张渲染面只消费：

```
同族锚点 = 分数最高的那一档（同分取最慢，再同取名字最大）
x = ln(锚点分数 / 本档分数)
y = ln((本档面积分数 / 锚点面积分数) / (本档 tok/s / 锚点 tok/s))
λ = max(0, Σxy / Σx²)            无可用数据或分母为 0 时 λ = 0
factor = clamp((index / global_max_index) ** λ, 0, 1)
radius = max(TASK_R_MIN, R_MAX * sqrt(area_fraction * factor))
```

- λ ≥ 0 是刻意的：只允许低分档变小，不允许把低分档放大成看着比高分档更大的球。
- **明确不推理的档位**（`non-reasoning` / `none`）在拟合前剔除，也不参与锚点选择：
  它们本来就不该被"分数低所以缩"这条同族规律解释。它们仍照常上图，仍吃同一个全局倍率。
- `minimal` / `min` / `low` 是真实推理档，必须留在拟合里，否则低分档会被系统性低估。
- 拟合只用画得出来的点（有效指数、正 tok/s、正官方任务耗时）；面积**定义域**与渲染面一致
  （官方正耗时优先，官方缺失才用派生估计；非正官方值不补估计），否则两侧的缩放域会不同。
- 半径下限仍是 `0.2·R_MAX`：收缩压到下限以下就停住，这是"看得见"对"精确比例"的取舍，
  也与缺耗时的最小空心圆保持区分。
- 旧载荷没有这块参数（或 λ=0）时开关禁用并在说明里写明"按原比例显示"，
  绝不拿 `factor=1` 冒充"已收缩"。
- 排序、Pareto 前沿、坐标一律不受影响；族卡与悬停说明跟着切换后的半径走。

`$REPO/data` 是**真目录**，里面由爬虫镜像出看板要用的 `latest.js` 与 `logos/`。
不要把它改成指向 `~/Library/Application Support/ModelRadar/data` 的软链 —— 看着更干净
（"真实字节只有一份"），实际会把看板弄坏：`~/Library` 是 0700，沙箱化的浏览器
（Safari）不跟软链进去，于是 `dashboard.html` 能打开、`<script src="data/latest.js">` 读不到，
页面只能显示"没读到数据"。权威状态（SQLite 历史 / `latest.json` / `chart.html`）仍只在
状态目录一份，镜像由 `write_outputs()` 每次抓取顺手做掉，所以两边不会漂。

## 什么时候会弹一条文字通知

判据只写在 `alert_policy` 一处，组件与爬虫都消费它的结论（`payload.alert`）。优先级从外到内：

| kind | 触发条件 | 标题语气 |
|---|---|---|
| `degraded` / `stale` / `empty` | 有源缺失 / 主源回落旧快照 / 完全没有数据 | warn「数据异常」 |
| `series-gone` | 上一轮 ≥3 档的能力线这一轮一档都不剩 | warn |
| **`moved`** | **本轮有变动过了门槛**：智能指数 >1 分、每任务成本 >20%、输出速度 >20%（`MOVE_RULES`；两条百分比门槛 2026-10-12 由 10% 提到 20%） | **info「值得注意的变动」** |
| **`moved-cumulative`** | **相邻两轮都不过门槛，但跟更早一轮比过了**：本轮 vs 往前第 2、3…轮逐个 diff，第一个过门槛的就报（`cumulative_moves`，上限 `CUMULATIVE_MAX_ROUNDS` 轮） | **info「值得注意的变动」** |
| `not-running` | 载荷龄 > 26h（**只能在读取侧判**，见上文） | warn |
| `fresh` | 其余情况 | 不弹，只亮角标 |

`moved-cumulative` 存在的理由：门槛量的是"相邻两轮的差"，而速度/单价常是每轮 3~8% 的慢漂移 ——
相邻比永远不过门槛，攒三五轮其实已经变了一大截。它单独一个 kind、单独一个去重键
（`alert:moved-cumulative:<日期>`），所以同一天里 `moved` 与它各响一次、互不抢；`moved` 优先。
浮层里三块内容有分工：**本轮自己有结论时只说本轮**（不再翻历史、也不再列累计，否则同一批条目
会被念三遍 —— 10-12 实测到过），安静轮才同时给"最近一次相邻过门槛"与"本轮 vs 更早一轮的累计"。
历史块与累计块条目完全相同时只留一份。

`moved` 的三点口径：① **通知只报 changed** —— 新入榜/掉榜有变动卡（脚注浮层另列一节，见下），整族消失有 `series-gone`，
混进来会被常规换榜刷成噪音；② 门槛是**严格大于**（+1 分、+10% 都不报）；③ 去重键
`alert:moved:<日期>`，一天最多响一次，同一天后续轮次里更大的变动并进同一条文案。
文案最多 200 字，按幅度从大到小列前 3 项，其余并成「…等 N 项」。

> ⚠️ 「数据异常」这个标题以前对所有非 `fresh` 一刀切，一条正常涨价也会顶着故障标题响。
> 现在语气由 `alert.tone`（`info` / `warn`）决定，Python 与 Swift 两侧同一份结论。

### 「抓取于 …」悬停：通知在原地能再读一次

通知一天只响一次，结论得有个地方回头看。悬停时间戳会弹出一块浮层，说清这几件事：

· **本轮结论**（`label` ＋ `kind`）与通知正文原样 —— 取自 `payload.alert`，跟弹出去的那条同源；
· **本轮没有达门槛变动时，往前翻台账找到最近一次有的那轮**，报出那一轮的时间、它当时对比的
  基线时间（`last_notable_round`，上限 `BACKTRACK_MAX_ROUNDS` 轮，翻不到就如实说翻了几轮）。
  动机是实测到的：11:40 那轮弹过 5 项、11:41 恢复 fresh，原地只剩"没有变动"，等于把刚发生的事抹掉。
  **本轮有变动时直接吃生产刚算的那份 `moves`，不重放台账**（重放与真榜不同形，会自打脸）；
  台账第 0 条必须是本轮，所以调用点排在 `save_diff_base` 之后（这条顺序有判据）；
  历史基线的**构造与词表筛选只有一处**（`baseline_map`）—— `load_previous` 会按当前词表把旧基线再筛一遍，
  回溯忘了筛就会报出生产根本不会报的变动（词表只增不减时看不出来，一次 `--refresh-watchlist` 变窄就分叉）；
· **达门槛的变动逐条列全，一条一行**（`· ` 前缀），不写"…等 N 项"。那种截断只属于通知横幅
  （系统对正文长度有上限）；浮层是给人读明细的，省略就等于少信息。爬虫因此把回溯结果按
  `items`（每条一项）下发，而不是只给拼好的一句；条目太多时浮层 `max-height + overflow:auto`
  可滚，不裁。故障类结论（源缺失 / 没跑）仍走 `alert.text`，不套列表。
· **同族合并的那一条后面挂「整族视角」**：`…；同族另有 3 档未到门槛（high -18.9%、…）；整族 5 档同向，
  均值 -20.8%、中位 -19.2%，区间 -27.9~-15.4%`。合并行本体只列过门槛的档，而一次调价通常是整族一起动的 ——
  只说两档会把一件事说小。门槛仍与 `notable_moves` 同源（`MOVE_RULES`），只是这里不把未到门槛的丢掉；
  整族都过了门槛时**不加尾巴**（那时合并行说的就是全部）。尾巴**只进浮层、不进通知横幅**（200 字上限），
  所以累计那一路同时给 `lines`（带尾巴）与 `lines_plain`（横幅用）。
· **每条后面跟一句「关联」读数**：`；关联：任务耗时(估) 1025.36→1374.43 秒（+34.0%），符合反比，
  偏差 +0.0 个百分点`。说的是另一项变了多少、本项有没有落到固定输出量下该有的那一格、差几个百分点；
  另一项没测到 / 没动 / 评测版本变了就直说 `数据不足` / `未变` / `评测版本变了，无法比较`，不硬算。
  判定容差 `INVERSE_TOL_PP = 5.0` 个百分点（实测 1450 对同轮变化：中位 0.0pp、p95 1.9pp，
  超过 5pp 只占 1.6%）。逐条只报数字，`同轮对比、非同比、不证明因果` 由最后一行 `move_hint()`
  统一说一次 —— 每条都带一遍会把数字挤没。
· **本轮之外还有"上次提示"，两个来源各给一节**（标题都带那一轮的时间与轮距）：
  ① `上次提示：<时间>（<kind>，往前第 N 轮）` —— 上一次**判定为会出声**的那条原文，
  来自 `.last_alert.json`；② `上次有达门槛变动的轮次：<时间>（往前第 N 轮，对比 <基线>）` ——
  台账 replay 出来的那一批（`prev_moves`，即 `last_notable_round(con, [], cfg)`，**强制**往前翻）。
  为什么两条都要：`moved` 的去重键按天算，同一天连响两轮时第二轮其实没出声 —— 只给 ②
  就会把"没弹过的轮次"说成"上次提示"；只给 ① 又漏掉"有变动但当天不再响"的情况。
  两条指向同一轮时并成一条标题，不重复念两遍。
  ① 只由**爬虫一侧**写（`will_pop` 与组件的弹不弹判据同源），所以组件读取侧改判的
  `not-running` 不在其中 —— 那种轮次由 ② 兜住。
  ① 还**只留得出内容的那类**：`should_record_alert = will_pop ∧ worth_remembering`，
  后者只看 `alert_policy` 已经算好的语气（`info` = 达门槛/累计变动；`warn` = 源降级、
  太久没跑、整族没了）。抓取失败也是"出声"，但它是"这一刻坏了"而不是"上次动了什么"，
  让它盖掉上一条真变动，浮层就会指着一次失败说"上次提示过这个"。所以失败轮**不覆盖**记录，
  等于自动往前留到上一次真变动；读取侧同样挡一道（写盘那条判据是后加的，磁盘上可能已经
  躺着一份 warn 记录，没有 tone 的老记录一律不认 —— 判不出就不瞎认）。语气清单不重复维护：
  两处都复用 `tone`，另列一份 kind 名单迟早一份改了另一份没改。轮距配的是台账 `ts` 不是 `generated_at`
  （两者各自调一次 `now_str()`，跨秒就错开一格），翻不到就只报时间、不编数字。
· **榜单进出**：`新进榜 N 个` 与 `落榜 N 个` **成对列**，一个名字一行。
  只报"新上了谁"不报"下去了谁"，读者就会以为榜单只在往上长 —— 这两个是同一件事的两面。
  它们始终不进 `notable_moves`（那里要"有基数的幅度"，而且每天常规换榜会把**通知**刷成噪音），
  变的只是浮层不再把读者支去看别处。派生只有一处：`board_io(changes)` 直接读 `type`，
  不另发一个载荷字段（那样同一份映射要在两侧对齐，而且得多等一轮抓取才看得见）。
· **改名不算榜单进出**：旧名消失、新名出现且两侧 `rename_identity` 唯一命中时，归成一条
  `type=renamed`，同族合成一句 `××：N 档改名（去掉 with fallback；…）`。
  判据是厂商 + 代次 + 档位（档位里的 `with fallback` / `default fallback` 不参与比较），
  两侧都有的 `aa_slug` / `or_id` 必须一致；候选不唯一或标识冲突就退回一进一出，不猜。
  改名不吞数据：提醒指标未过门槛才标"未达变化门槛"，过门槛仍进 `notable_moves`；
  单价变化、缺值与评测版本变化也一律不标静默。2026-11-06 实测三族（Opus 5.5 / Sonnet 5.5 /
  Fable 5.1）各 5 档去掉 `with fallback`，此前会报成 15 个新进榜 + 15 个落榜。
  其中 Opus 的智能指数与三项价格逐项相同，TPS/任务耗时变化约 0.5%～1.4%，TTFT 最大 +15.8%。
· **门槛文案**由 `move_hint()` 从 `MOVE_RULES` 现拼，改常量跟着变。

去重键不再展示（内部键，读者不需要）。回溯与真实 diff 共用同一套配对（相邻两轮 +
同一个 `notable_moves`），名次/用量也共用同一份重放 —— 排序若各写一遍，两条路径会对
"第几名"给出不同答案（这条有专门的判据与变异）。

**浮层是页面自己画的（`.tip > .bub` + `:hover`），不是原生 `title`。** 实测原因：popover 的宿主是
`.accessory` 的 app，它永远激活不了（`NSApp.isActive` 恒 false），而 AppKit 对非活跃 app 的 tooltip
默认不画（新建窗口 `allowsToolTipsWhenApplicationIsInactive` 默认 false）——`cursor:help` 那个问号
出来了，提示框却不弹。`:hover` 与图上圆点高亮同机制，不依赖系统行为。两个坑记在这里：
① 浮层的定位上下文必须是整条 `.foot`（`position:relative` 在 `.foot` 上）；挂回内联的 `.tip` 上，
绝对定位会按那个 span 的 ~140px 宽做 shrink-to-fit，四行挤成一根竖条（实测 530×84 → 141×221）；
② 注入面从"关掉属性"换成"关掉标签"，`<` 一样要转义（`html.escape(tip, quote=False)` 就够，
文本里的裸引号无害）。

### 图例 / 族卡联动悬停：整厂一眼看全

图上 13 家厂商、82 个档位，光靠颜色认"这家有哪些点"很慢。现在：

· **顶栏「▤ 卡片」开关**：统一控制出不出卡（族卡与综述卡一起管），关掉后悬停只高亮。
  状态存 `UserDefaults`（键 `cardsOn`，默认开），每次页面加载完由宿主 `evaluateJavaScript`
  把 `window.MR_CARDS` 推进去；共享 JS 只认这一个全局量，**没设就是开**，
  所以直接用浏览器打开 chart.html 时行为不变。
· **悬停图例格** → 这家全部档位（含能力线）搬进顶层、放大加粗，并弹：
  ① **综述卡**（每厂一张）：头部是三项指标各给区间与中位（`智能指数`、`每任务成本`、`输出速度`），
  再给一行时间与比例的厂商中位（`任务耗时`、`思考时间`、`思考前摇`），
  下面**按系列一行**：`系列名 · 档位选项 · 智能指数范围 · 最优档`。
  最优档 = 该系列**在 Pareto 前沿上**那些档里分数最高的。**只有真在前沿上才加"（前沿）"标注**
  （10-13 用户口径）：整族被支配时那一档只是"这族里最高的"，后缀一个"（不在前沿）"会把
  要标的和不用标的拉成一样长，标注意义就没了 —— 那一档照给，只是不标。
  只有一个点就没有可比的兄弟档 → 最优档那栏**留空**（原先那句"单点不成族"是解释不是数据）。
  推估与参照带**不再各占一行解释**（10-13 用户口径），但逐档行里照旧带 `≈900` / `56–106`
  的标记 —— 删的是重复说明，不是口径。"实测 N 档"因此就是字面意思：只含实测，
  推估并进同一个区间就是把估计当实测说，而图上早就用虚线环把它们分开了。
  ② **各系列的族卡**：一张都不省，全贴（按 `data-pri`，最强族先）。
· **悬停单个气泡** → 只亮它**那一族**，并弹该族那一张**合并弹窗**：表头是系列与档位数，
  下面**每一档一行**（`档位 · 双评分 · $每任务 · 任务耗时(估) · 思考时间 · 思考前摇 · tok/s`，
  按固定推理档位反序）——"不再逐点贴卡，但每个点的详述都在"就是这一条。
· **族卡一律贴在"该族中心点"的左上角**（卡右下角对着那颗球），不按左右侧翻转。
  中心点 = 按智能指数排序后居中的那一档（两档的族质心会并列，所以按数据取中位而不是按像素距离，
  两侧才不会各自认一颗球）。球太靠上、卡片比上面的空隙还高时**只许顶到边界**（此时会盖住自己的球），
  不许换侧——换侧等于卡片离球太远，认不出说的是哪一族。
· **共有尾巴只标一次**：`low with fallback / … / max with fallback` 抽成
  `low/…/max（均 with fallback）`。这是排版收敛（一行 540px 会把综述卡撑到一种形状都放不下），
  但口径一个字不丢——判据专门盯着"抽完还在不在"。
· **卡片是平级兄弟**（`<g class="chip fam|lg" data-k data-c data-pri data-anchor data-r0>`），
  不在 `.mk` 子树里：整族高亮那步会给 `.mk` 加 `scale(1.45)`，卡片待在子树里就被一起放大成 14.5px 的字。
  搬运与恢复仍走同一套 `home`（父节点 + 下标），收起时连卡一起回位。
  `.chip` 必须 `pointer-events:none` —— 卡片一吃指针，事件 target 就变成卡片，
  `closest('[data-k]')` 落空走延迟收起，又回到 2026-09-29 那种自激闪烁。
· **塌缩**：显示前按**引擎实际字宽**量文字并集，把背景矩形收到"并集 + 内边距"，
  然后**整组平移**把钉住的那一角放回作者侧的位置（`data-r0` 是基准；只挪矩形不挪字，
  实测 7 行文字全部出框；拿当前 rect 当基准，重复悬停会一路漂）。
· **综述卡的形状与落点是算出来的**：`panel_shapes` 枚举每栏行数（长行先折行，折行可逐字还原），
  只试**左下与右下**两个角（10-13 用户口径：不压帕累托右上角那句标注），
  取**压到的数据点更少**的那个 —— 压点比压空白严重得多。
  `fit_count` 还在，但只在两角之间择优用，**不再写进产物**：它曾以 `data-fit` 充当
  "JS 至少能贴上这么多"的下界，而 JS 现在会绕球换角、还会取压得最少的候选位，
  两边不同构，比出来的大小不成立（实测 1 < 2）。
· **避让不是"就不显示"**：找不到空位也照显，只是**衬到别的卡底下**，
  并落在**压得最少**的那个候选位上（候选序 = 作者位 → 绕中心球换四角 → 上下左右错开一格，
  全部夹在 `data-plot` 报给 JS 的绘图区里）。叠放序一律按 `data-pri` **倒序**画，
  沉底那批也不例外 —— 按处理序画就成了"赢家垫底、输家盖着它"，与"衬到底下"正好相反。
  卡片单独一个 `<g class="cards">`，永远是 `.toplayer` 的第一个孩子，
  所以点与连线天然浮在卡片上面（用户口径），卡片内部谁压谁只取决于组内顺序。

判据落点：`tools/test_rules.py` 的 `TestLegendHover`（20 条）＋ `verify_dashboard.mjs` 的
`popover：…`（静态形状/数字复算/尾巴不丢）与 `行为：…`（把**产物这张 SVG** 喂给共享 JS 模拟
pointer：整厂高亮、别家不牵连、**该厂族卡零隐藏**、重叠只许"分数低的衬在分数高的底下"、
每张卡的屏上位仍在绘图区内且只落在合法候选位、综述卡贴在左下/右下角、

把它们各自的落点钉死。数字复算按 `load_points` 的口径

## 变动总结（可选增强，找不到 AI 就只显示表格）

看板里的「最近一次抓取的变动」有两种显示：**没有可用的总结命令时平铺逐条表格**（绝大多数机器的
常态，不是错误）；**有总结时显示一段人话，逐条明细收进悬停**。总结按内容指纹配对，数据一更新，
上一段话就不再属于今天，自动退回表格。

分工是不可交换的（`summarize.py`）：

1. Python 先把事实算成一张**事实卡**：谁变了、从几到几、幅度、几族改名、几个新上榜/掉榜、哪些值第一次
  出现，外加从 SQLite 里算好的**近 7 天**变化（单日 diff 常常只有零点几个点，周尺度才是读者想知道的）。
  改名由 `rename_lines(changes)` 同族合成一句，不让模型逐档复述或说成换榜。
2. 命令行工具只许把事实卡改写成 2~4 句中文，**不许自己算任何数** —— 也不许引用外部知识。
3. 回读校验：文本里出现的每个数字都必须在事实卡里找得到（只放过四舍五入与去尾零两种写法，
   **不留相对容差**，否则 100% 被写成 102% 就查不出来）。有一个数对不上就整段丢弃，退回表格。
   这段是整个方案的支点：一段编得很顺的错误总结比没有总结更糟，而它看上去一模一样。
4. 显示时标明「机器生成 · 悬停看逐条」，并且**转义后再进 innerHTML** —— 它的输入包含远端页面上的
   模型名，不转义等于把 DOM 开放给远端内容。

### 单价变动的归因

输入/输出单价来自 OpenRouter 目录里**匹配到的那一条**，每任务成本来自 AA。两者不同源，所以会
出现"单价 +531% 而每任务成本一分没动"这种矛盾（本机实测：`z-ai/glm-5.3` 在 07:30→14:06 之间
从 0.2219 变到 1.4，AA 侧 0.85 未变）。变动卡因此给单价挂归因标签：

- **匹配对象换了：旧 id → 新 id** —— 价格不是变的，是我们换到了另一个目录条目。
- **AA 每任务成本未变** —— 两个源说法矛盾，别把它读成"厂商涨价"。

`or_id` 因此进变动基线（`DIFF_ATTR`），但它**不进 `DIFF_FIELDS`**：那是数值比对表，混进去会被
算成百分比。基线里没有这个键的老数据（本次改动之前存的）只标第二条、不宣称"没换" —— 缺证据
不等于证明了没换。

配不配置都在运行时目录，源码里没有任何工具名：

```bash
# 本机用哪个免费 CLI 写总结。不配就是"没有总结"，看板照常显示表格。
# 模板里只放可执行程序与参数：提示词由程序作为最后一个 argv 附上（见上面的说明）。
cat > ~/Library/Application\ Support/ModelRadar/summary_cmd <<'CMD'
bash ~/path/to/你的只读CLI包装 -C {dir} -o {out} --timeout {timeout}
CMD
# 要满足三件事：只读（不写文件）、零计费、上下文全新。产物写进 -o 指定的文件即可。
# 也可以走环境变量：MODELRADAR_SUMMARY_CMD='...'
# 临时关掉：MODELRADAR_NO_SUMMARY=1（抓取与总结解耦，抓取本身不因为它失败）
```

占位符 `{dir} {out} {timeout}` 由程序替换，**提示词作为最后一个 argv 交给命令**，绝不拼进
shell 字符串（模型名来自远端页面，拼 shell 就是命令注入的入口）。总结在**分离的子进程**里跑，
抓取不等待它 —— 组件给"↻ 立即抓取"的超时是 240s，把一分多钟的模型调用接在尾巴上，症状会是
"脚本超时"而数据其实早写好了。

## 三条设计约束（改动前请先读）

**1. 判据单点定义。** 坐标、配色、Pareto 前沿、`data_state`、内容指纹全在 Python 侧算完，
组件只消费。同一套逻辑散在两处，改一处忘另一处就是静默翻车。

**2. 组件不硬编码路径。** 一切问 `runtime.env`。以前是在 Application Support 下给
`chart.html`/`latest.json`/`dashboard.html` 各建一条软链指回仓库 —— 那是把"仓库在哪"
这个易变事实固化成三条链，仓库一挪就断，而断链的表现和真故障长得一模一样。
⚠️ `runtime.env` 的值**必须带双引号**：`Application Support` 含空格，不加引号时 bash 的
`. file` 会把路径截断、把后半截当命令执行（Swift 侧按行解析不受影响，所以只在壳脚本里炸）。

**3. 换版生效是 build 脚本的活，不是运行时的活。** 组件启动时不杀旧实例、心跳时不自我替换，
只发现"磁盘二进制更新了"并在 ⋯ 菜单里给出「重启以应用新版本」。运行时自动换版的代价是
"我看到的界面是哪一版"不可复现 —— 2026-09-28 那次审查期间二进制被自动换掉，直接干扰了判断。
